# i18n frontend - Cilentomania HUB

## Lingue supportate
- it
- en
- de
- fr
- es

## Struttura
- i18n/it.json
- i18n/en.json
- i18n/de.json
- i18n/fr.json
- i18n/es.json
- js/i18n.js

## API globale
Il modulo espone `window.CilentomaniaI18n` con:
- `getCurrentLanguage()`
- `setLanguage(language)`
- `t(key, fallback)`
- `applyTranslations(rootElement)`
- `getSupportedLanguages()`
- `normalizeLanguage(language)`

## Priorita lingua
1. lingua salvata in `localStorage` (`cilentomania_language`)
2. lingua del browser se supportata
3. fallback italiano

La scelta manuale ha sempre priorita.

## Attributi markup
- `data-i18n="path.key"` -> testo elemento (`textContent`)
- `data-i18n-placeholder="path.key"` -> placeholder
- `data-i18n-aria-label="path.key"` -> aria-label
- `data-i18n-title="path.key"` -> title

## Come aggiungere una chiave
1. Aggiungi la chiave in `i18n/it.json`.
2. Aggiungi la stessa chiave negli altri file lingua.
3. Aggiungi attributo `data-i18n*` nel markup oppure usa `CilentomaniaI18n.t(...)` in JS dinamico.

## Come aggiungere una nuova lingua
1. Crea `i18n/<lang>.json`.
2. Aggiungi la lingua in `SUPPORTED_LANGUAGES` in `js/i18n.js`.
3. Verifica il selettore lingua e il fallback.

## Controllo chiavi mancanti
Per evitare divergenze tra dizionari usa lo script:

```bash
node tools/check-i18n-keys.js
```

Lo script confronta `it.json` con `en/de/fr/es` e segnala:
- chiavi mancanti
- chiavi extra

Regola operativa: ogni nuova chiave UI va inserita prima in `it.json` e poi replicata nelle altre lingue.

## Reazione al cambio lingua
Alla modifica viene emesso l'evento:
- `cilentomania:languagechange`
con `detail.language` valorizzato (`it|en|de|fr|es`).

I moduli dinamici possono ascoltarlo:
```js
document.addEventListener('cilentomania:languagechange', (event) => {
  const language = event.detail.language;
  // refresh rendering
});
```

## Fallback per chiave mancante
`CilentomaniaI18n.t` cerca la chiave:
1. nella lingua corrente
2. nel dizionario italiano
3. nel fallback passato a funzione

In questo modo i testi non diventano vuoti.

## Chat Cilentino
Il frontend invia sempre il campo `language` nel payload chat con valore normalizzato (`it|en|de|fr|es`).

Esempio:
```json
{
  "message": "Where can I stay in Castellabate?",
  "language": "en"
}
```

Nota: in questa fase non viene tradotta automaticamente la risposta backend; il backend puo continuare a rispondere in italiano.

## Contenuti non ancora tradotti
Rimangono in italiano i contenuti lunghi/editoriali:
- schede complete dei Comuni
- descrizioni estese
- dataset completi eventi/itinerari/strutture/ristoranti

## Strategia futura contenuti lunghi
Scelta consigliata: **file traduzioni separati per lingua e ID** (modello B).

Motivi:
- niente duplicazione dei dataset principali
- aggiornamenti mirati per singolo contenuto
- fallback italiano semplice
- migliore scalabilita su migliaia di record

Schema consigliato:
- dataset principale in italiano (record sorgente)
- file secondari `data/translations/<lang>/<dataset>.json` con:
  - `content_id`
  - `fields` tradotti
  - metadati di stato/qualita

### Versionamento sorgente e aggiornamento traduzioni
Quando il contenuto italiano viene creato o modificato:
1. calcolare o aggiornare una `source_version` (hash o versione incrementale);
2. confrontare la `source_version` del record italiano con quella associata a ciascuna traduzione;
3. se diversa, marcare la traduzione come `da_aggiornare`;
4. lasciare il fallback italiano attivo finché non esiste una nuova traduzione valida.

In questa fase non viene chiamato alcun servizio AI e non vengono rigenerati dataset automaticamente.

## Stato traduzioni (proposta)
Per ogni traduzione:
- `non_tradotto`
- `ai_generata`
- `in_revisione`
- `verificata`
- `da_aggiornare`

Metadati consigliati:
- `language`
- `content_id`
- `source_version`
- `generated_at`
- `verified_at`
- `reviewer`
- `model`
- `notes`

Esempio minimo di metadato traduzione:

```json
{
  "content_id": "castellabate",
  "language": "en",
  "source_version": "comuni.castellabate.v12",
  "status": "da_aggiornare",
  "generated_at": "2026-07-27T10:00:00Z",
  "verified_at": null,
  "reviewer": null,
  "model": "gpt-5.3-codex",
  "notes": "Sorgente italiana aggiornata"
}
```

Regola: usare sempre prima `verificata`; se il contenuto italiano cambia, segnare le traduzioni correlate come `da_aggiornare`.
